# merchant-category-classifier

카드 명세서에 찍히는 **상호명(merchant string)**을 업종/지출 카테고리로 분류하는 실험.
[ktc4-pusan-4](https://github.com/kakaotechcampus-4) 룰카드 세무판정 시스템의 카테고리 분류(현재 키워드/정규식 기반)를,
공개 **소상공인 상가(상권)정보**로 학습한 char n-gram + 선형분류기로 보강할 수 있는지 검증한다.

> **결론 요약:** 오프라인 소비 업종(음식점·카페·편의점·미용·의료 등 17개)에는 실제로 작동한다.
> 온라인/공과금/금융/정부 성격의 15개 카테고리는 공개 상가데이터에 **구조적으로 존재하지 않아** 분류 대상이 아니다 → 키워드 룰의 몫.

> 📄 **규칙 vs 하이브리드 비교 결과와 근거는 [REPORT.md](REPORT.md) 참고.**
> (실제 카드셋에서 정확도 0.60 → 0.82, 커버리지 63% → 100%, confidence cutoff ≈ 0.45)
>
> 🏗️ **분류 파이프라인 제안(다이어그램 포함)은 [ARCHITECTURE.md](ARCHITECTURE.md) 참고.**
> (캐시 → 규칙 → 상가업소 API → 분류기 → review → write-back)

## 방법

- **데이터**: 공공데이터포털 [소상공인시장진흥공단_상가(상권)정보](https://www.data.go.kr/data/15083033/fileData.do) (17개 시도 CSV zip). 상호명 + 상권업종 대/중/소분류 + 표준산업분류.
- **전처리**: 상호명 단위로 dedup(majority 라벨). 같은 이름이 train/test에 걸쳐 정확도가 부풀려지는 leakage 방지.
- **모델**: `HashingVectorizer(char_wb, 2~4gram, 2^20)` + `SGDClassifier(log_loss)`. CPU만으로 수분.
- **평가**: 상호명 dedup 후 80/20 stratified split. accuracy / macro-F1.
- **32-cat 매핑**: 상권 중분류(75종) → ktc4-pusan-4 32개 카테고리 매핑표(`mapping.py`). gold/pred 둘 다 매핑해 비교.

## 결과 (전국, 상가정보 2026-06 기준)

유효행 2,772,484 / 고유 상호명 1,845,837.

| 라벨 체계 | 클래스 수 | accuracy | macro-F1 |
|---|---:|---:|---:|
| 상권 대분류 | 10 | 0.806 | 0.804 |
| 상권 중분류 | 75 | 0.699 | 0.606 |
| **중분류 → 32-cat 매핑** | 17(도달) | **0.765** | 0.726 |

- 중분류(75)에서 서로 헷갈리던 클래스(한식↔중식↔서양식 등)가 같은 32-cat(`음식점`)으로 합쳐지며 **정확도가 회복**된다(0.699 → 0.765).
- **잘 되는 카테고리**: 의료 0.96, 미용 0.85, 차량 0.85, 음식점 0.84, 임차료 0.84, 교육 0.82, 편의점 0.80.
- **약한 카테고리**: 광고 0.50, 사무용품 0.45, 수리비 0.58 — 이름에 업종 단서가 없는 추상 서비스나 성격이 섞인 잡화.

### 도달 범위 (핵심)

```
도달 가능 (17): 카페 음식점 편의점 차량 미용 의료 교육 광고 전자기기
               생활용품 여가 여비교통 임차료 전문가수수료 수리비 사무용품 기타
도달 불가 (15): 온라인쇼핑 음식배달 해외SaaS 국내SW 통신 수도광열 도서
               금융 지자체_과태료 경찰청_범칙금 조세 PG_미상 게임 구독서비스 보험
```

도달 불가 15개는 **데이터가 부족해서가 아니라 문제 성격이 달라서**다.
고정 브랜드(통신·전기·금융·보험·배달·구독)는 사전 한 줄이면 되고,
거래 성격 라벨(조세·과태료·범칙금·PG_미상·해외SaaS)은 "상호명→업종" 문제가 아니라 규칙/키워드의 영역이다.
데이터 보강 실익이 있는 건 온라인쇼핑·도서 롱테일(→ 통신판매업 데이터) 정도.

## 도메인 시프트 (중요한 한계)

학습 데이터의 상호명은 **깨끗한 등록명**(`○○카페 강남점`)이고, 카드 명세서 문자열은
정규화·지점명·카드사 태그가 붙은 형태(`○○카페강남`, `구글플레이`, `○○_문화비`)라 분포가 다르다.

- 오프라인 프랜차이즈는 지점명이 붙어도 char n-gram이 브랜드 부분문자열을 잡아 **높은 확신도로 정확**.
- 온라인/해외 결제(앱마켓·해외SaaS 등)는 애초에 데이터에 없어 **오답이지만 확률(p)이 낮게** 나오는 경향 → confidence threshold로 review 라우팅에 활용 가능(단, OOD 탐지를 보장하진 않음).

> ⚠️ 위 in-domain 0.765는 **상가데이터 라벨을 매핑한 수치**이지, 실제 카드 명세서에 정답을 붙여 잰 값이 아니다.
> 진짜 성능은 카드 문자열에 32-cat 정답을 라벨링해 측정해야 한다. (개인 금융데이터라 이 저장소에는 포함하지 않음)

## 사용법

```bash
pip install -r requirements.txt

# 상권 중분류 학습 + 32-cat 매핑 성능
python train.py --zip "소상공인시장진흥공단_상가(상권)정보_YYYYMM.zip" --level middle --map32

# 상권 대분류(10클래스)
python train.py --zip DATA.zip --level major

# 임의 CSV(raw_merchant 컬럼)에 예측 찍어보기(1회성)
python train.py --zip DATA.zip --level middle --map32 --predict merchants.csv
```

### 모델 저장 후 반복 예측 (재학습 없이 수초)

매번 학습(수분)하지 말고, 한 번 저장해 로드한다:

```bash
# 1회: 학습 후 저장
python train.py --zip DATA.zip --level middle --save-model model.joblib

# 이후 반복: 로드해서 예측만(수초)
python predict.py --model model.joblib --input merchants.csv -o out.csv
```

> 모델은 해시 2^20이라 수백 MB다 → **로컬 캐시**로만 쓰고 커밋하지 않는다(`.gitignore`).

## 파일

- `train.py` — 스트리밍 로딩 / 학습 / 평가 / 32-cat 매핑 / 모델 저장 CLI.
- `predict.py` — 저장된 모델 로드 → CSV 예측(재학습 없음).
- `mapping.py` — 상권 중분류(75) → 32-cat 매핑표 + 도달 가능/불가 목록.
